# Breast Cancer Classification

Predicts malignant vs. benign breast cancer diagnosis from 9 biopsy-derived clinical
features, comparing four classification algorithms with an emphasis on **recall**
(minimizing missed cancer cases) rather than raw accuracy alone.

## Dataset

- **Source:** [`cancer.csv`](https://raw.githubusercontent.com/swapnilsaurav/MachineLearning/refs/heads/master/cancer.csv)
- **Size:** 683 rows × 10 columns → **449 rows** after removing 234 duplicate records (34.3%)
- **Target:** `Class` — `0` (benign) / `1` (malignant)
- **Features (9):** `age`, `menopause`, `tumor-size`, `inv-nodes`, `node-caps`, `deg-malig`,
  `breast`, `breast-quad`, `irradiat` — all encoded as integer scores (1–10 scale)

> **Note:** the duplicate rows removed were heavily skewed toward Class 0 (97.9% benign vs.
> 65% benign overall) — meaning the mild class imbalance seen after cleaning (53% malignant /
> 47% benign) was largely introduced by deduplication itself, not an inherent property of the
> raw data. Worth keeping in mind if you re-run this on a refreshed data pull.

## Usage

1. Open `Classification_Cancer_analysis.ipynb` in Jupyter and run all cells top to bottom
   (the dataset is pulled directly from the URL above, no manual download needed).
2. This regenerates `cancer_prediction_pipeline.pkl`, a single bundled
   `scikit-learn` `Pipeline` (scaler + model) used for inference.
3. To predict on a new patient:

```python
import joblib
import pandas as pd

pipeline = joblib.load("cancer_prediction_pipeline.pkl")

new_patient = pd.DataFrame([{
    "age": 6, "menopause": 4, "tumor-size": 4, "inv-nodes": 3, "node-caps": 3,
    "deg-malig": 4, "breast": 4, "breast-quad": 3, "irradiat": 4,
}])

predicted_class = pipeline.predict(new_patient)[0]           # 0 = benign, 1 = malignant
predicted_prob = pipeline.predict_proba(new_patient)[0][1]   # probability of malignancy
```

## Pipeline Overview

1. **Data cleaning** — checked for missing values (none) and duplicates (234 removed, see
   note above on the class-balance implication of that step).
2. **Train/test split** — 80/20, performed *before* any resampling to avoid leakage.
3. **Class imbalance check** — the post-cleaning split is only ~53%/47%, a mild imbalance.
   Random Under Sampler, Random Over Sampler, and SMOTE were all benchmarked directly
   against a "no balancing" baseline, using the same held-out test set — **all four gave
   identical performance** (Accuracy 0.978, Recall 1.0), confirming that resampling wasn't
   actually necessary for this particular imbalance. SMOTE was still carried forward as
   the technique for the rest of the notebook.
4. **Scaling** — `StandardScaler`, fit on the training data only. A scale-then-SMOTE vs.
   SMOTE-then-scale check confirmed no difference here (all 9 features already share the
   same 1–10 scale), but scale-first is noted as the more robust default in general.
5. **Modeling** — four classifiers trained and compared: Logistic Regression, K-Nearest
   Neighbors, Decision Tree, and Random Forest.
6. **Evaluation** — accuracy, precision, recall, F1, ROC AUC, confusion matrices, and ROC
   curves for all four models, plus feature importance for the tree-based models.
7. **Deployment** — scaler and final model bundled into a single `sklearn.Pipeline` and
   serialized with `joblib`, so inference never risks using a mismatched scaler/model pair.

## Results

| Model | Accuracy | Precision | Recall | F1 | ROC AUC |
|---|---|---|---|---|---|
| Logistic Regression | 0.978 | 0.959 | **1.000** | 0.979 | 0.998 |
| KNN | 0.989 | 0.979 | **1.000** | 0.990 | 0.986 |
| **Random Forest** | **0.989** | **0.979** | **1.000** | **0.990** | **0.9995** |
| Decision Tree | 0.956 | 0.939 | 0.979 | 0.958 | 0.955 |

**Deployed model: Random Forest** — tied for the best accuracy/recall, and the highest ROC
AUC of the group. Three of the four models achieve **perfect recall** (zero missed cancer
cases on this test set); Decision Tree alone misses one malignant case.

> The test set is only 90 patients, so a 1-patient difference shifts accuracy by over a
> percentage point — treat the small gaps between Logistic Regression / KNN / Random Forest
> as close to a tie rather than a definitive ranking without cross-validation.

## Key Findings

- **Recall, not accuracy, is the metric that matters here** — a false negative means a
  missed cancer diagnosis. Logistic Regression, KNN, and Random Forest all achieve perfect
  recall (1.0); only Decision Tree misses a case.
- Resampling techniques (SMOTE, RUS, ROS) made **no measurable difference** vs. training on
  the original, mildly-imbalanced data — a useful sanity check before assuming balancing is
  always necessary.
- Duplicate removal wasn't class-neutral: it disproportionately dropped benign records,
  which is what shifted the dataset from 65% benign to a near-even split.
- Random Forest's higher ROC AUC (0.9995 vs. 0.998 for Logistic Regression) indicates it
  ranks malignancy risk more reliably across all thresholds, not just at the default cutoff.
- Bundling the scaler and model into one `Pipeline` object removes a real deployment
  footgun: forgetting to scale new data (or scaling it with the wrong scaler) before
  prediction.
